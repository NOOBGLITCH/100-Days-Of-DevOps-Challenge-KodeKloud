# Deploy Guestbook Application on Kubernetes

The Nautilus Application Development team completed the Guestbook application and requested a three-tier Kubernetes deployment consisting of **Redis Master**, **Redis Slave**, and a **PHP Frontend**. The application was deployed using separate YAML files for each component.

## Requirements

### Back-End Tier

* Create Deployment **`redis-master`**
* Create Service **`redis-master`**
* Create Deployment **`redis-slave`**
* Create Service **`redis-slave`**
* Create Service **`redis-follower`**

### Front-End Tier

* Create Deployment **`frontend`**
* Create NodePort Service **`frontend`**
* Expose the application on **NodePort 30009**

---

# Steps

## 1. Let's create `k3s-redis-master.yaml` file and copy-paste the following Redis Master YAML

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: redis-master
spec:
  replicas: 1
  selector:
    matchLabels:
      app: redis-master
  template:
    metadata:
      labels:
        app: redis-master
    spec:
      containers:
      - name: master-redis-nautilus
        image: redis
        resources:
          requests:
            cpu: 100m
            memory: 100Mi
        ports:
        - containerPort: 6379
---
apiVersion: v1
kind: Service
metadata:
  name: redis-master
spec:
  selector:
    app: redis-master
  ports:
  - port: 6379
    targetPort: 6379
```

Create the resources:

```sh
kubectl apply -f k3s-redis-master.yaml
```

---

## 2. Let's create `k3s-redis-slave.yaml` file and copy-paste the following Redis Slave YAML

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: redis-slave
spec:
  replicas: 2
  selector:
    matchLabels:
      app: redis-slave
  template:
    metadata:
      labels:
        app: redis-slave
    spec:
      containers:
      - name: slave-redis-nautilus
        image: gcr.io/google_samples/gb-redisslave:v3
        env:
        - name: GET_HOSTS_FROM
          value: dns
        resources:
          requests:
            cpu: 100m
            memory: 100Mi
        ports:
        - containerPort: 6379
---
apiVersion: v1
kind: Service
metadata:
  name: redis-slave
spec:
  selector:
    app: redis-slave
  ports:
  - port: 6379
    targetPort: 6379
---
apiVersion: v1
kind: Service
metadata:
  name: redis-follower
spec:
  selector:
    app: redis-slave
  ports:
  - port: 6379
    targetPort: 6379
```

Create the resources:

```sh
kubectl apply -f k3s-redis-slave.yaml
```

---

## 3. Let's create `k3s-php-redis.yaml` file and copy-paste the following PHP Frontend YAML

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend
spec:
  replicas: 3
  selector:
    matchLabels:
      app: guestbook
  template:
    metadata:
      labels:
        app: guestbook
    spec:
      containers:
      - name: php-redis-nautilus
        image: gcr.io/google-samples/gb-frontend@sha256:a908df8486ff66f2c4daa0d3d8a2fa09846a1fc8efd65649c0109695c7c5cbff
        env:
        - name: GET_HOSTS_FROM
          value: dns
        resources:
          requests:
            cpu: 100m
            memory: 100Mi
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: frontend
spec:
  type: NodePort
  selector:
    app: guestbook
  ports:
  - port: 80
    targetPort: 80
    nodePort: 30009
```

Create the resources:

```sh
kubectl apply -f k3s-php-redis.yaml
```

# Good to Know?

### Redis Master

* Handles all write operations.
* Stores the primary copy of application data.
* Runs as a single replica.

### Redis Slave

* Replicates data from Redis Master.
* Improves read performance and scalability.
* Uses `GET_HOSTS_FROM=dns` to discover Redis Master through Kubernetes DNS.

### Frontend

* PHP-based Guestbook application.
* Communicates with Redis services using Kubernetes DNS.
* Exposed externally through a NodePort Service.

### Kubernetes Services

* **ClusterIP** provides internal communication between application components.
* **NodePort** exposes the frontend outside the cluster on a fixed port.

### Resource Requests

Each container reserves:

* **CPU:** `100m`
* **Memory:** `100Mi`
