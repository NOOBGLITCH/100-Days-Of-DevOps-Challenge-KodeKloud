# Terraform EC2 Instance Provisioning

Create an EC2 instance using Terraform with the following specifications. The Terraform working directory is `/home/bob/terraform`. All configuration must be placed in a single `main.tf` file.

-   **Name Tag**: `xfusion-ec2`
-   **AMI**: `ami-0c101f26f147fa7fd` (Amazon Linux)
-   **Instance Type**: `t2.micro`
-   **Key Pair**: Create a new RSA key named `xfusion-kp`
-   **Security Group**: Attach the default security group
-   **File**: `/home/bob/terraform/main.tf` (single file only)

> **Note:** Right-click under the EXPLORER section in VS Code and select **Open in Integrated Terminal** to launch the terminal.

## Steps

1.  Navigate to the Terraform working directory:

    ```sh
    cd /home/bob/terraform
    ```

2.  Create the `main.tf` file:

    ```sh
    vi main.tf
    ```

3.  Add the following Terraform configuration:

    ```hcl
    provider "aws" {
      region = "us-east-1"
    }

    resource "tls_private_key" "xfusion_kp" {
      algorithm = "RSA"
      rsa_bits  = 4096
    }

    resource "aws_key_pair" "xfusion_kp" {
      key_name   = "xfusion-kp"
      public_key = tls_private_key.xfusion_kp.public_key_openssh
    }

    data "aws_security_group" "default" {
      filter {
        name   = "group-name"
        values = ["default"]
      }
    }

    resource "aws_instance" "xfusion_ec2" {
      ami             = "ami-0c101f26f147fa7fd"
      instance_type   = "t2.micro"
      key_name        = aws_key_pair.xfusion_kp.key_name
      vpc_security_group_ids = [data.aws_security_group.default.id]

      tags = {
        Name = "xfusion-ec2"
      }
    }
    ```

4.  Initialize Terraform:

    ```sh
    terraform init
    ```

5.  Review the execution plan:

    ```sh
    terraform plan
    ```

6.  Apply the configuration to provision the resources:

    ```sh
    terraform apply -auto-approve
    ```

7.  Verify the EC2 instance was created correctly:

    ```sh
    aws ec2 describe-instances --filters "Name=tag:Name,Values=xfusion-ec2" --query 'Reservations[0].Instances[0].[InstanceId,State.Name,InstanceType,KeyName]' --output table
    ```

## Good to Know

### Terraform AWS Provider

-   **Region Configuration**: Always explicitly set the `region` in the provider block to avoid ambiguity and ensure reproducible deployments.
-   **Authentication**: The AWS provider uses environment variables (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`), shared credentials file, or IAM role for authentication automatically.
-   **API Versioning**: Pin provider versions in production using `required_providers` to prevent breaking changes during upgrades.

### TLS Private Key Resource

-   **In-Memory Generation**: The `tls_private_key` resource generates the RSA key pair entirely within Terraform state; no external SSH keygen command is needed.
-   **Key Export**: The private key is stored in state as PEM format via `tls_private_key.xfusion_kp.private_key_pem` and can be exported using `terraform output` if needed.
-   **Algorithm Options**: Supports RSA, ECDSA, and ED25519; RSA 4096-bit is recommended for broad compatibility with AWS EC2.

### Data Sources vs Resources

-   **Data Sources**: Read-only lookups for existing infrastructure (e.g., `data.aws_security_group.default`); they do not create or modify anything.
-   **Resources**: Manage the lifecycle of infrastructure objects (create, update, delete); Terraform tracks their state.
-   **Default Security Group**: Every VPC has a default security group that allows all inbound traffic from members of the same group and all outbound traffic; referencing it via data source avoids creating duplicate rules.

### EC2 Instance Best Practices

-   **Tagging Strategy**: The `Name` tag is used by AWS Console and CLI for human-readable identification; always include it for operational clarity.
-   **Key Pair Management**: Each key pair should have a unique name per environment to avoid conflicts during parallel deployments.
-   **Instance Metadata**: Use `user_data` for bootstrapping scripts and `metadata_options` to enforce IMDSv2 for enhanced security.
-   **State Sensitivity**: Private keys and sensitive attributes are stored in Terraform state; encrypt state files at rest and restrict access in production environments.
