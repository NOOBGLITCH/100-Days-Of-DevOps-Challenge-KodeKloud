# Jenkins Pipeline: Conditional Branch Deployment on App Server using Jenkins

The development team at **xFusionCorp Industries** is building a static website stored in a **Gitea** repository. The application is already cloned on **App Server 1** under `/var/www/html`. The objective is to configure a **Jenkins Pipeline** that can deploy either the **master** or **feature** branch based on a user-provided parameter.

This guide walks through installing the required plugins, configuring the Jenkins agent, creating a parameterized pipeline, and verifying the deployment.

---

# Lab Requirements

* **Jenkins Job:** `datacenter-webapp-job`
* **Job Type:** Pipeline (Not Multibranch Pipeline)
* **Repository:** `web_app`
* **Repository Location:** `/var/www/html`
* **Agent Name:** `App Server 1`
* **Agent Label:** `stapp01`
* **Remote Root Directory:** `/home/sarah/jenkins_agent`
* **Parameter:** `BRANCH`
* **Stage Name:** `Deploy`

> **Note:** The repository is already cloned on App Server 1. The pipeline only needs to switch branches and pull the latest changes.

---

# Step 1: Install Required Jenkins Plugins

Navigate to:

**Manage Jenkins → Plugins**

Install:

* Pipeline
* SSH Build Agents

Restart Jenkins if prompted.

# Step 2: Install OpenJDK on App Server 1

SSH into App Server 1 using the **sarah** user.

```bash
ssh sarah@stapp01
```

```bash
sudo yum install -y java-21-openjdk
```

Or install OpenJDK 17:



Create the workspace directory:

Navigate to:

**Manage Jenkins → Nodes → New Node**

Configure the agent as follows:

| Setting                        | Value                               |
| ------------------------------ | ----------------------------------- |
| Name                           | App Server 1                        |
| Type                           | Permanent Agent                     |

# Step 6: Create the Pipeline Job

Create a new Jenkins item.

| Setting  | Value                   |
| -------- | ----------------------- |
| Job Name | `datacenter-webapp-job` |
| Type     | Pipeline                |

---

# Step 7: Configure the String Parameter

Enable:

**This project is parameterized**

Add a **String Parameter**:

| Field         | Value            |
| ------------- | ---------------- |
| Name          | `BRANCH`         |
| Default Value | `master`         |
| Description   | Branch to deploy |

---

# Step 8: Configure the Pipeline

Select:

**Pipeline → Definition → Pipeline Script**

Paste the following pipeline:

```groovy

pipeline {
    agent { label 'stapp01' }

    parameters {
        string(name: 'BRANCH', defaultValue: 'master', description: 'Enter branch name: master or feature')
    }

    stages {
        stage('Deploy') {
            steps {
                script {
                    if (params.BRANCH == 'master') {
                        sh '''
                        cd /var/www/html
                        git fetch --all
                        git checkout master
                        git pull origin master
                        '''
                    } 
                    else if (params.BRANCH == 'feature') {
                        sh '''
                        cd /var/www/html
                        git fetch --all
                        git checkout feature
                        git pull origin feature
                        '''
                    } 
                    else {
                        error "Invalid branch name. Use 'master' or 'feature'."
                    }
                }
            }
        }
    }
}
```

Save the job.

# Good to Know

## OpenJDK Installation

Jenkins agents require a supported Java version to communicate with the Jenkins controller.

Install Java 21:

```bash
sudo yum install -y java-21-openjdk
```

Or Java 17:

```bash
sudo yum install -y java-17-openjdk
```

Verify:

```bash
java -version
```

---

## Jenkins Agents

* **Distributed Builds:** Jobs execute on remote machines instead of the Jenkins controller.
* **Labels:** Labels such as `stapp01` allow Jenkins to target a specific agent.
* **Remote Workspace:** `/home/sarah/jenkins_agent` stores Jenkins workspace files.
* **Correct User:** Configure the SSH agent using **sarah**, the repository owner, to avoid permission issues.

---

## Parameterized Pipelines

* Deploy different Git branches using a single pipeline.
* Select the branch at runtime using the **BRANCH** parameter.
* Simplify CI/CD by avoiding multiple deployment jobs.

---

## Conditional Deployment

The pipeline checks the value of the **BRANCH** parameter:

* `master` → Deploys the production branch.
* `feature` → Deploys the feature branch.

This enables safe testing of new features without affecting the production branch.

---

## Git-Based Deployment

Since the repository is already cloned:

* `git fetch origin` downloads the latest changes.
* `git checkout` switches branches.
* `git pull origin <branch>` updates the selected branch.

This approach is faster and simpler than cloning the repository during every build.

---

## Static Website Deployment

Apache serves files directly from:

```
/var/www/html
```

Deploying directly to the document root ensures the website is available immediately without requiring an Apache restart.

---

## SSH Credentials

Jenkins connects to the agent using SSH.

For this lab:

| Username | Password        |
| -------- | --------------- |
| `sarah`  | `Sarah_pass123` |

Using the repository owner's account eliminates the need for `sudo` inside the pipeline.

# Common Issues

## UnsupportedClassVersionError

**Cause**

The agent is running an older Java version.

**Solution**

Install OpenJDK 17 or OpenJDK 21.

---

## Agent Offline

Possible causes:

* Java not installed
* Incorrect SSH credentials
* Missing Remote Root Directory
* SSH connectivity issues

---

## Still Waiting to Schedule Task

Usually caused by:

* Incorrect node label
* Offline agent
* Zero executors configured
* Typographical errors in the pipeline label

---

## Permission Denied

If Git operations fail with permission errors:

* Ensure the Jenkins agent connects as **sarah**.
* Avoid changing repository ownership unnecessarily.
* Do not use `sudo` in the pipeline unless explicitly required.

---

# Key Lessons Learned

* Install a supported Java version (17 or 21) before configuring Jenkins agents.
* Configure the Jenkins SSH agent using the **repository owner's account (`sarah`)**.
* Parameterized pipelines make branch-based deployments simple and reusable.
* Reuse the existing Git repository instead of cloning it during every build.
* Keep pipelines simple by avoiding unnecessary privilege escalation.
* Verify the deployment locally and through the Load Balancer before running the lab validator.
