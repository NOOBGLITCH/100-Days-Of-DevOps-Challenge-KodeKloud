# Create IAM Policy Using Terraform

When establishing infrastructure on the AWS cloud, Identity and Access Management (IAM) is among the first and most critical services to configure. IAM facilitates the creation and management of user accounts, groups, roles, policies, and other access controls. The Nautilus DevOps team is currently in the process of configuring these resources and has outlined the following requirements.

Create an IAM policy named `iampolicy_john` in `us-east-1` region using Terraform. It must allow read-only access to the `EC2 console`, i.e., this policy must allow users to view `all instances`, `AMIs`, and `snapshots` in the Amazon EC2 console.

The Terraform working directory is `/home/bob/terraform`. Create the `main.tf` file (do not create a different .tf file) to accomplish this task.

> **Note:** Right-click under the EXPLORER section in VS Code and select **Open in Integrated Terminal** to launch the terminal.

## Steps

1.  Navigate to the Terraform working directory and create a `main.tf` file with the following contents:

    ```sh
    cd /home/bob/terraform
    vi main.tf
    ```

    ```hcl
    resource "aws_iam_policy" "policy" {
      name        = "iampolicy_john"
      path        = "/"
      description = "Read-only access to EC2 console for viewing instances, AMIs, and snapshots"

      policy = jsonencode({
        Version = "2012-10-17"
        Statement = [
          {
            Action = [
              "ec2:Describe*",
            ]
            Effect   = "Allow"
            Resource = "*"
          },
        ]
      })

      tags = {
        Name = "iampolicy_john"
      }
    }
    ```

2.  Run the Terraform commands:

    ```sh
    terraform init
    terraform plan
    terraform apply -auto-approve
    ```

3.  Verify the IAM policy was created correctly:

    ```sh
    aws iam get-policy --policy-arn arn:aws:iam::$(aws sts get-caller-identity --query Account --output text):policy/iampolicy_john
    ```

## Good To Know

-   **IAM Policy Structure**: Uses JSON format with Version, Statement, Effect, Action, and Resource fields.
-   **ec2:Describe\*** wildcard covers all EC2 read operations including instances, AMIs, snapshots, volumes, security groups, and more.
-   **Resource "\*"** grants access to all EC2 resources across the account; describe operations are generally account-level and do not support resource-level ARN filtering.
-   **Effect "Allow"** explicitly permits the specified actions; without an explicit Allow, access is denied by default.
-   **Policy Attachment**: This managed policy must be attached to users, groups, or roles via `aws_iam_user_policy_attachment`, `aws_iam_group_policy_attachment`, or `aws_iam_role_policy_attachment` to take effect.
-   **Least Privilege**: Read-only access using `Describe*` follows the security best practice of granting minimal permissions necessary for console visibility without allowing modifications.
