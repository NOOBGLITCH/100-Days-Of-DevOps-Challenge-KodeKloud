# Create AWS VPC, Subnet & EC2 Instance Using Terraform

Create a private VPC environment with a subnet and EC2 instance using Terraform. The configuration must use separate `variables.tf`, `data.tf`, `outputs.tf`, and `main.tf` files.

-   **VPC**: `xfusion-priv-vpc` with CIDR `10.0.0.0/16`
-   **Subnet**: `xfusion-priv-subnet` with CIDR `10.0.1.0/24`, auto-assign public IP disabled
-   **EC2 Instance**: `xfusion-priv-ec2`, type `t2.micro`, inside the subnet
-   **Security Group**: Allow access only from within the VPC's CIDR block
-   **Working Directory**: `/home/bob/terraform`

> **Note:** Right-click under the EXPLORER section in VS Code and select **Open in Integrated Terminal** to launch the terminal. Before submitting, ensure `terraform plan` returns **No changes. Your infrastructure matches the configuration.**

## Steps

1.  Navigate to the Terraform working directory:

    ```sh
    cd /home/bob/terraform
    ```

2.  Create the `variables.tf` file:

    ```sh
    vi variables.tf
    ```

    ```hcl
    variable "KKE_VPC_CIDR" {
      description = "CIDR block for the VPC"
      default     = "10.0.0.0/16"
    }

    variable "KKE_SUBNET_CIDR" {
      description = "CIDR block for the subnet"
      default     = "10.0.1.0/24"
    }
    ```

3.  Create the `data.tf` file:

    ```sh
    vi data.tf
    ```

    ```hcl
    data "aws_ami" "amazon_linux" {
      most_recent = true
      owners      = ["amazon"]

      filter {
        name   = "name"
        values = ["amzn2-ami-hvm-*-x86_64-gp2"]
      }
    }
    ```

4.  Create the `main.tf` file:

    ```sh
    vi main.tf
    ```

    ```hcl
    provider "aws" {
      region = "us-east-1"
    }

    resource "aws_vpc" "xfusion_vpc" {
      cidr_block = var.KKE_VPC_CIDR

      tags = {
        Name = "xfusion-priv-vpc"
      }
    }

    resource "aws_subnet" "xfusion_subnet" {
      vpc_id                  = aws_vpc.xfusion_vpc.id
      cidr_block              = var.KKE_SUBNET_CIDR
      map_public_ip_on_launch = false

      tags = {
        Name = "xfusion-priv-subnet"
      }
    }

    resource "aws_security_group" "xfusion_sg" {
      name        = "xfusion-priv-sg"
      description = "Allow access only from within the VPC CIDR block"
      vpc_id      = aws_vpc.xfusion_vpc.id

      ingress {
        from_port   = 0
        to_port     = 0
        protocol    = "-1"
        cidr_blocks = [var.KKE_VPC_CIDR]
      }

      egress {
        from_port   = 0
        to_port     = 0
        protocol    = "-1"
        cidr_blocks = ["0.0.0.0/0"]
      }

      tags = {
        Name = "xfusion-priv-sg"
      }
    }

    resource "aws_instance" "xfusion_ec2" {
      ami                    = data.aws_ami.amazon_linux.id
      instance_type          = "t2.micro"
      subnet_id              = aws_subnet.xfusion_subnet.id
      vpc_security_group_ids = [aws_security_group.xfusion_sg.id]

      tags = {
        Name = "xfusion-priv-ec2"
      }
    }
    ```

5.  Create the `outputs.tf` file:

    ```sh
    vi outputs.tf
    ```

    ```hcl
    output "KKE_vpc_name" {
      description = "Name of the VPC"
      value       = aws_vpc.xfusion_vpc.tags["Name"]
    }

    output "KKE_subnet_name" {
      description = "Name of the subnet"
      value       = aws_subnet.xfusion_subnet.tags["Name"]
    }

    output "KKE_ec2_private" {
      description = "Name of the EC2 instance"
      value       = aws_instance.xfusion_ec2.tags["Name"]
    }
    ```

6.  Run the Terraform commands:

    ```sh
    terraform init
    terraform plan
    terraform apply -auto-approve
    ```

7.  Confirm no changes remain (required before submission):

    ```sh
    terraform plan
    ```

    > Expected output: **No changes. Your infrastructure matches the configuration.**

8.  Verify outputs:

    ```sh
    terraform output
    ```

    > Expected output:

    ```text
    KKE_ec2_private = "xfusion-priv-ec2"
    KKE_subnet_name = "xfusion-priv-subnet"
    KKE_vpc_name    = "xfusion-priv-vpc"
    ```

## Good To Know

-   **Separation of Concerns**: Splitting configuration into `variables.tf`, `data.tf`, `main.tf`, and `outputs.tf` improves readability and maintainability as infrastructure grows.
-   **Data Sources**: The `data.tf` file isolates read-only lookups (e.g., AMI discovery) from resource definitions, making it easy to update data queries without touching provisioning logic.
-   **VPC CIDR Block**: `10.0.0.0/16` provides 65,536 IP addresses; the subnet `10.0.1.0/24` allocates 256 addresses (251 usable after AWS reserves 5 per subnet).
-   **map_public_ip_on_launch**: Setting this to `false` ensures instances do not receive public IPs automatically, keeping them private and accessible only within the VPC.
-   **Security Group Ingress**: Using the VPC CIDR (`10.0.0.0/16`) as the ingress source restricts all inbound traffic to originate only from within the VPC, blocking external access entirely.
-   **Protocol "-1"**: In AWS security group rules, protocol `-1` means "all protocols" (TCP, UDP, ICMP), effectively allowing or denying all traffic types on the specified CIDR.
-   **Dynamic AMI Lookup**: Using `data "aws_ami"` with `most_recent = true` dynamically fetches the latest Amazon Linux 2 AMI, avoiding hardcoded AMI IDs that may become deprecated.
-   **Terraform Outputs**: Output values provide a convenient way to extract and display key resource attributes after provisioning, useful for verification and downstream automation.
-   **Variable Defaults**: Defining default values in `variables.tf` allows `terraform apply` to run without interactive prompts or additional `-var` flags.
