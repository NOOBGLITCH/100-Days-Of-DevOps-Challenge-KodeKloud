# Managing Jinja2 Templates Using Ansible

Complete the following tasks to configure an httpd role with a dynamic Jinja2 template for App Server 3:

a. Update `~/ansible/playbook.yml` playbook to run the `httpd` role on App Server 3.
b. Create a jinja2 template `index.html.j2` under `/home/thor/ansible/role/httpd/templates/` directory and add a line `This file was created using Ansible on <respective server>`. Do not hard code the server name; use the `inventory_hostname` variable instead.
c. Add a task inside `/home/thor/ansible/role/httpd/tasks/main.yml` to copy this template on App Server 3 under `/var/www/html/index.html`. Ensure the file permissions are set to `0777`.
d. The user/group owner of `/var/www/html/index.html` must be the respective sudo user of the server (e.g., `banner` for `stapp03`).

> **Note:** Validation will try to run the playbook using command `ansible-playbook -i inventory playbook.yml` so please make sure the playbook works this way without passing any extra arguments.

## Steps

0.  Move into the ansible directory and inspect existing files:

    ```sh
    cd ~/ansible
    ls
    cat inventory
    cat playbook.yml
    ls role/httpd
    ```

1.  Update `ansible.cfg` to ensure roles and inventory resolve correctly:

    ```sh
    vi ansible.cfg
    ```

    > Make sure it contains:

    ```ini
    [defaults]
    host_key_checking = False
    roles_path = /home/thor/ansible/role
    inventory = /home/thor/ansible/inventory
    ```

2.  Create the `index.html.j2` template file:

    ```sh
    vi role/httpd/templates/index.html.j2
    ```

    > Add the following content:

    ```j2
    This file was created using Ansible on {{ inventory_hostname }}
    ```

3.  Update the role's `main.yml` task file:

    ```sh
    vi role/httpd/tasks/main.yml
    ```

    > Replace contents with:

    ```yaml
    ---
    - name: Create web root directory
      ansible.builtin.file:
        path: /var/www/html
        state: directory
        owner: "{{ ansible_user }}"
        group: "{{ ansible_user }}"

    - name: Copy index.html template
      ansible.builtin.template:
        src: index.html.j2
        dest: /var/www/html/index.html
        mode: '0777'
        owner: "{{ ansible_user }}"
        group: "{{ ansible_user }}"
    ```

4.  Update `playbook.yml` to target App Server 3 (`stapp03`):

    ```yaml
    ---
    - name: Run httpd role on App Server 3
      hosts: stapp03
      become: true

      roles:
        - httpd
    ```

5.  Run the playbook:

    ```sh
    ansible-playbook -i inventory playbook.yml
    ```

6.  Verify permissions, ownership, and content on App Server 3:

    ```sh
    ssh banner@stapp03
    ls -la /var/www/html/index.html
    cat /var/www/html/index.html
    ```

    > Expected output:
    > ```text
    > -rwxrwxrwx 1 banner banner 48 Aug 22 10:00 /var/www/html/index.html
    > This file was created using Ansible on stapp03
    > ```

## Good to Know

### Jinja2 Templating in Ansible

-   **Dynamic Content**: Use `{{ variable }}` syntax to inject runtime values into templates
-   **Magic Variables**: `inventory_hostname` always reflects the inventory name, while `ansible_hostname` reflects the target system’s actual hostname
-   **Template Location**: When used inside a role, `src:` paths are relative to the role’s `templates/` directory
-   **No Hardcoding**: Always prefer variables over static strings to maintain reusability across environments

### Template Module Best Practices

-   **Idempotency**: The `template` module only transfers the file if the rendered content differs from the destination
-   **Permissions**: Always quote octal modes (e.g., `'0777'`) to prevent YAML from interpreting them as integers
-   **Ownership**: Use `{{ ansible_user }}` to dynamically assign ownership based on the connecting user
-   **Validation**: Consider adding `validate:` parameter for configuration files to catch syntax errors before deployment

### Role Directory Convention

-   **tasks/main.yml**: Entry point for role execution; contains the primary task list
-   **templates/**: Stores `.j2` files processed by the template module
-   **files/**: Stores static files copied without templating
-   **vars/ & defaults/**: Define role-specific variables at different precedence levels

### Security Considerations

-   **Permission 0777**: Grants read, write, and execute to all users; typically discouraged in production but may be required for specific testing scenarios
-   **Owner Matching**: Setting both user and group to `{{ ansible_user }}` ensures consistency when the sudo user varies per host
-   **Host Key Checking**: Disabling via `ansible.cfg` simplifies automation but should be managed carefully in secure environments
