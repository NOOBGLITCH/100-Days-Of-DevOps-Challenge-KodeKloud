# Troubleshoot and Create Ansible Playbook

An Ansible playbook needs completion on the **jump host**, where a team member left off. The inventory must be updated to target **App Server 2** in Stratos DC, and a playbook must be created to generate an empty file on that server.

## Requirements

* Update `/home/thor/ansible/inventory`
* Target **App Server 2**
* Create `/home/thor/ansible/playbook.yml`
* Create an empty `/tmp/file.txt` on App Server 2
* The playbook must work with:

```bash
ansible-playbook -i inventory playbook.yml
```

---

# Steps

## 0. Move into the Ansible directory

```bash
cd /home/thor/ansible
ls
```

---

## 1. Fix the Inventory File

Open the inventory:

```bash
vi inventory
```

App Server 2 details:

```text
Hostname: stapp02
Username: steve
Password: Am3ric@
```

Replace the existing entry with:

```ini
[app_servers]
stapp02 ansible_host=stapp02 ansible_user=steve ansible_ssh_password=Am3ric@ ansible_ssh_common_args='-o StrictHostKeyChecking=no'
```

### Why these variables are required

* `ansible_host=stapp02` — connects to App Server 2
* `ansible_user=steve` — SSH user
* `ansible_ssh_password=Am3ric@` — SSH password
* `ansible_ssh_common_args='-o StrictHostKeyChecking=no'` — prevents host-key checking from blocking password-based SSH

---

## 2. Optional: Configure SSH Key and Known Hosts

If you want to add the server to SSH's known hosts instead, generate an SSH key if one does not already exist:

```bash
ssh-keygen -t ed25519
```

You can accept the default location by pressing **Enter**.

Add App Server 2 to `known_hosts`:

```bash
ssh-keyscan -H stapp02 >> ~/.ssh/known_hosts
```

Test SSH:

```bash
ssh steve@stapp02
```

Enter:

```text
Am3ric@
```

Then exit:

```bash
exit
```

For this lab, the inventory configuration using:

```ini
ansible_ssh_common_args='-o StrictHostKeyChecking=no'
```

is sufficient and avoids requiring additional SSH options during validation.

---

## 3. Test the Inventory

From `/home/thor/ansible`:

```bash
ansible all -i inventory -m ping
```

Expected:

```text
stapp02 | SUCCESS => {
    "changed": false,
    "ping": "pong"
}
```

If you get `UNREACHABLE`, check the hostname, username, and password in `inventory`.

---

## 4. Create `playbook.yml`

Create the playbook:

```bash
vi playbook.yml
```

Add:

```yaml
---
- name: Create file on App Server 2
  hosts: app_servers
  gather_facts: false

  tasks:
    - name: Create an empty file
      ansible.builtin.file:
        path: /tmp/file.txt
        state: touch
```

Save and exit.

---

## 5. Check the Playbook Syntax

Run:

```bash
ansible-playbook -i inventory playbook.yml --syntax-check
```

Expected:

```text
playbook: playbook.yml
```

---

## 6. Run the Playbook

Run the exact command specified by the validation:

```bash
ansible-playbook -i inventory playbook.yml
```

Expected output will be similar to:

```text
PLAY [Create file on App Server 2]

TASK [Create an empty file]
changed: [stapp02]

PLAY RECAP
stapp02 : ok=1 changed=1 unreachable=0 failed=0
```

---

## 7. Verify the File

SSH into App Server 2:

```bash
ssh steve@stapp02
```

Check:

```bash
ls -l /tmp/file.txt
```

Or verify directly from the jump host:

```bash
ssh steve@stapp02 "test -f /tmp/file.txt && echo 'File exists'"
```

Expected:

```text
File exists
```

## Good to Know?

### Ansible Troubleshooting

- **Connection Issues**: Verify SSH connectivity and credentials
- **Inventory Problems**: Check host definitions and variables
- **Module Errors**: Validate module syntax and parameters
- **Permission Issues**: Ensure proper sudo/root access

### Common Issues

- **Host Unreachable**: Network connectivity problems
- **Authentication Failed**: Wrong credentials or SSH keys
- **Module Not Found**: Missing Ansible modules
- **Syntax Errors**: YAML formatting issues

### Debugging Techniques

- **Verbose Mode**: Use `-v`, `-vv`, `-vvv` for detailed output
- **Check Mode**: Use `--check` for dry-run execution
- **Limit Hosts**: Use `--limit` to target specific hosts
- **Step Mode**: Use `--step` for interactive execution

### File Operations

- **file Module**: Create, modify, delete files and directories
- **copy Module**: Copy files from control node to managed nodes
- **template Module**: Process Jinja2 templates
- **lineinfile Module**: Modify specific lines in files
